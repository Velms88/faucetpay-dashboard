Полезные скрипты, генерация тестовых данных, FAQ по самым частым багам.

## 1. Доступные npm-скрипты (`package.json`)

```json
{
  "scripts": {
    "init-db": "node init_db.js",
    "start": "npx serve ."
  }
}
```

| Скрипт | Назначение |
|--------|-----------|
| `npm run init-db` | **Создать структуру БД Turso**. Запускается один раз при поднятии нового экземпляра БД. Выполняет `CREATE TABLE IF NOT EXISTS` по 4 таблицам. |
| `npm run start` | Запустить локальный dev-сервер через `npx serve .` на порту 3000 (открывайте `http://localhost:3000`). |

## 2. Запуск пайплайна локально (без GitHub Actions)

Чтобы протестировать build_faucets.js на своей машине перед коммитом:

### Шаг 1. Создайте локальный `.env` (не коммитьте!) или пропишите переменные окружения временно:

```powershell
# PowerShell 5 (Windows)
$env:TURSO_URL = "libsql://your-db.turso.io"
$env:TURSO_TOKEN = "eyJhbGciOiJSUzI1NiI..."
$env:COINGECKO_API = "CG-..."
$env:FAUCETPAY_API_KEY = "fp_live_..."
```

### Шаг 2. Сначала сделайте **DRY-RUN** (без записи в БД!)

```cmd
node build_faucets.js --dry-run --mock-prices
```

В stdout выведутся:
- Общее количество кранов в faucets.json
- Сколько строк будет добавлено в `raw_hourly`
- Топ-5 кранов по рейтингу с расшифровкой по блокам
- Суммарный капитал всех кранов USD

### Шаг 3. Если всё ок — запустите полную синхронизацию

```cmd
node build_faucets.js --fetch-prices
```

## 3. Генерация тестовых данных

Если вы хотите разработать UI без доступа к реальной Turso БД (офлайн, локально, без интернета) — используйте два генератора синтетических данных.

### 3.1 Сгенерировать 50 фейковых кранов в faucets.json

```cmd
node generate_mock_faucets.js --count 50
```

Создаст `faucets.json` с рандомными названиями, категориями, монетами. Не содержит никакой реальной информации.

### 3.2 Сгенерировать 30 дней истории (raw_hourly)

```cmd
node generate_mock_history.js --days 30
```

Заполнит БД или локальный кэш 30 днями почасовых снимков для всех кранов. Удобно проверять медианы 7d, поведение payout_activity_hours и т. д.

## 4. 8.3 Частые проблемы и их решения (FAQ / Troubleshooting)

Самые часто задаваемые вопросы разработчиков проекта.

| Симптом | ✅ Вероятная причина | ✅ Как исправить |
|---------|-----------------------|-----------------|
| **Ошибка `Blocked by file:// protocol` / Fetch API не работает / blank page** | Вы открыли `index.html` двойным кликом, а не через локальный сервер. Браузер блокирует `file://`. | Запустите `npm run start` или `python -m http.server 8000`. Откройте `http://localhost:3000` или `http://localhost:8000`. |
| **Таблица пустая (0 записей) / NaN везде** | 1) Turso не отвечает.<br>2) Секрет `TURSO_URL` неправильный.<br>3) Таблицы `faucets` пустые (ещё ни разу не запущен пайплайн). | 1) Откройте Network Tab → убедитесь что Turso возвращает 200.<br>2) Запустите Actions workflow `Fetch Faucets` вручную → убедитесь зелёный.<br>3) Если локально — запустите `node build_faucets.js --fetch-prices`. |
| **Высвечивается старая версия `app.js` с прошлого деплоя (написано v=30, а в коде v=34)** | Дисковый HTTP-кэш браузера. | 1) Увеличьте суффикс `?v=XX` в [index.html](../index.html#L53-L55).<br>2) Нажмите **«⟳ Обновить»** на дашборде или **Ctrl+Shift+R** (hard reload). |
| **Сессия в админке истекает каждые 5 минут — что не так?** | Пользователь закрыл вкладку / `sessionStorage` очищен, либо время компьютера сбилось на прошлое. | 1) Не закрывайте вкладку.<br>2) Проверьте дату/время ОС.<br>3) Введите токен заново. |
| **Рейтинг = 0 / F у всех кранов, которые точно не мёртвые** | 1) Веса Блоков 1–4 в `config.mode='prod'` все выставлены в 0 (0%).<br>2) `is_enabled` таргеты для этих кранов = 0.<br>3) Ошибка формулы (последний коммит сломал ratingCalculator.js). | 1) Откройте админпанель → Настройки формулы → проверьте веса, сумма >= 0.1.<br>2) Проверьте targets_moderation `is_enabled`.<br>3) Откатите последний коммит с правкой ratingCalculator.js. |
| **`npm run init-db` падает с ошибкой `Database not found`** | `TURSO_URL` не выставлен или БД в Turso не создана. | 1) Создайте БД в консоли Turso Dashboard.<br>2) Скопируйте `libsql://` URL и JWT токен из `Turso_DB_Connection.md` в переменные окружения. |
| **Ошибка `429 Too Many Requests CoinGecko` в пайплайне** | Public endpoint исчерпал rate-limit (10–30 rpm). | 1) Купите CoinGecko Pro / Demo API и добавьте секрет `COINGECKO_API`.<br>2) Или запустите локально с `--mock-prices`. |
| **Payout activity hours всегда 169 часов (максимум) у топ кранов** | Накрутка `total_users_paid` при нулевом `paid_today`. | Эта проблема **исправлена** в версии ratingCalculator.js ≥ v33 (тройная антинакрутка: trigger A / B / C + POST-PROCESSING override). Запустите пайплайн ещё раз + нажмите «⟳ Обновить». |
| **Workflow Actions постоянно падает на шаге `npm ci`** | Плохое интернет-соединение раннера или временный сбой npm registry. | Нажмите **Re-run failed jobs** один раз. Если не помогает — закэшируйте npm_modules через `actions/cache@v4` в workflow. |
| **Цвета бейджей не совпадают с заявленными (Health/Рейтинг)** | Старая версия `style.css?v=5` кэширована. | Увеличьте суффикс `?v=` для `<link rel="stylesheet" href="./style.css?v=XX">` в [index.html](../index.html#L7). |

## 5. Рекомендации по локальной разработке

1. Всегда запускайте `node build_faucets.js --dry-run` **перед** любым изменением ratingCalculator.js / healthScore.js — сравните топ-10 старый vs новый, убедитесь что рейтинги изменились предсказуемо.
2. Никогда не работайте с основным `prod`-режимом конфига при разработке формул. Используйте отдельный `mode='dev'` в таблице `config`.
3. Напишите скрин-тест на 10 кранов: `p1` = рейтинг на текущем коммите → `git stash` → `p2` = рейтинг → сравнивайте дельту между `p1` и `p2` только по ожидаемым кранам.
4. Делайте маленькие коммиты: «feat(health): fix low-capital coefficient», «chore(docs): add ARCHITECTURE.md». Не смешивайте логику формул и стили CSS в одном коммите.

## 6. Cache-busting — забываемое правило

**КАЖДЫЙ раз**, когда вы вносите изменения в JS-файлы или CSS — **обязательно инкрементируйте версию (`?v=XX`)** в [index.html](../index.html), иначе пользователи будут видеть старый код из дискового кэша браузера неделями:

```html
<!-- index.html -->
<link rel="stylesheet" href="./style.css?v=6">            <!-- было v=5 → стало v=6 -->
<script src="./cryptoPrices.js?v=2"></script>             <!-- было v=1 → стало v=2 -->
<script src="./app.js?v=35"></script>                     <!-- было v=34 → стало v=35 -->
```
