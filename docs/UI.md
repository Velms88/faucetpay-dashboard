# Пользовательский интерфейс (UI)

Описание главной таблицы дашборда, всех её колонок, фильтрации, сортировки и кэширования.

---

## 1. Верхняя панель (Header)

```
┌─────────────────────────────────────────────────────────────────────────┐
│   📊 FaucetPay Monitor Dashboard   [⚙️ Админпанель]   [⟳ Обновить]      │
│   Всего кранов: 1846   ·   Последнее обновление: 2026-09-29 15:13 UTC  │
└─────────────────────────────────────────────────────────────────────────┘
```

| Элемент | Что делает |
|---------|-----------|
| **Заголовок** `📊 FaucetPay Monitor Dashboard` | Название проекта |
| Кнопка **`⚙️ Админпанель`** | Открывает модалку входа в админпанель (пароль UI + WRITE-READ токен Turso). Подробнее — [Админпанель](ADMIN_PANEL.md). |
| Кнопка **`⟳ Обновить`** | **Форсированный сброс** браузерного IndexedDB-кэша `snapshots` → все данные скачиваются заново из Turso БД. Используйте, если таблица показывает старые данные после деплоя. |
| Статистика `Всего кранов: N` | Количество строк в таблице `faucets` с `is_enabled=1`. |
| Строка **Последнее обновление** | ISO-метка `updated_at` самого свежего снимка в `raw_hourly`. |

## 2. Поиск и фильтрация

Поле быстрого поиска работает по **4 полям одновременно**:
1. Название крана (name, регистронезависимо)
2. URL-адрес (включая подстроки)
3. Категория (Faucet / PTC / Offerwall и т. д.)
4. Список монет (BTC, LTC, DOGE и т. п.)

Реализация — функция `getFiltered()` в [app.js](../app.js).

Примеры:
- Введите `bitcoin` → останутся краны с монетой BTC и словом «bitcoin» в названии.
- Введите `ptc` → только категория PTC.
- Введите `123bit` → найдётся `123bit.com`.
- Оставьте пустым → показываются **все** краны.

## 3. Колонки главной таблицы

Всего 13 колонок. Описание каждой:

| № | Название колонки | Тип | Описание | Где в БД |
|--:|-----------------|-----|----------|----------|
| 1 | **Название** | текст + 📋 Copy | Название крана. Клик по 📋 копирует URL крана в буфер обмена. | `faucets.name`, `faucets.url` |
| 2 | **Тип** | бейдж | Тип выплаты: `Auto` / `Manual` / `Mixed` (синий/жёлтый/красный). | `faucets.payout_type` или таргет модерации. |
| 3 | **Блок 1** | % / 100 | **Платёжеспособность**: daily_volume + health + payout_activity. | `faucets.block_1_solvency` |
| 4 | **Блок 2** | % / 100 | **Надёжность**: возраст + тип выплат + кол-во шлюзов. | `faucets.block_2_reliability` |
| 5 | **Блок 3** | % / 100 | **UII (User Index Indicator)**: ручная оценка модератора 0–100. | `targets_moderation.uii_points` |
| 6 | **Блок 4** | % / 100 | **Bonus Points**: бонусные баллы (или штрафы, если отрицательные) от модерации. | `targets_moderation.bonus_points` |
| 7 | **MAX баланс 7d** | USD $ | Максимальный капитал крана (USD) за последние 7 дней по всем снимкам `raw_hourly`. | `MAX(raw_hourly.total_balance_usd)` |
| 8 | **Выплат за 24h** | целое число | **Количество** успешных выплат за сутки. `0` при нулевом объёме (антинакрутка). | `faucets.total_users_paid` |
| 9 | **Выплачено сегодня** | USD $ | **Объём** всех выплат за сутки ($). | `faucets.paid_today` |
| 10 | **Капитал** | USD $ | Текущий капитал (баланс всех монет × курс). | `faucets.current_capital` |
| 11 | **Здоровье (Health Score)** | цветной бейдж 0–100 | Текущий Health Score. Цвет: зелёный ≥ 80, жёлтый 50–80, оранжевый 20–50, красный < 20. | `raw_hourly.current_health` (последний снимок) |
| 12 | **Рейтинг** | бейдж A–F + число 0–100 | Финальный взвешенный рейтинг. Цвет зависит от A+:золото → F:тёмно-красный. | **Рассчитывается локально** `clientCalc.calculateRating()` + колонка `faucets.rating` как fallback. |
| 13 | **Метка** | текст/эмодзи | `LEGIT` / `SCAM` / `NEW` / `МОЙ`. Задаётся модератором. | `targets_moderation.label` |

> 💡 При наведении на ячейки «Блок 1 – 4», «Здоровье», «Рейтинг» появляется всплывающий tooltip с полным расчётом по формуле (какие пороги и веса сработали).

## 4. Сортировка

**Клик по заголовку колонки** переключает порядок:  
`Нет сортировки` → `По убыванию (⬇️)` → `По возрастанию (⬆️)` → `Нет сортировки`.

По умолчанию главная таблица сортируется по **`Рейтинг DESC`** (вверху лучшие краны с A+ и 100 баллами).

Колонки, по которым нельзя сортировать: «Название» (сортируется по URL), «Метка» (только фильтр в админке).

## 5. Пагинация

Под таблицей:

```
  ⏮ Previous   Page 1 of 93  ⏭ Next   [ Show 25 ▾ entries per page ]
```

| Элемент | Что делает |
|---------|-----------|
| `⏮ Previous` / `⏭ Next` | Переключение страниц. Блокируются на первой и последней странице. |
| `Page N of M` | Текущая страница / всего страниц. |
| `Show [N] entries per page` | **Выбор размера страницы**: `20`, `25` (по умолчанию), `50`, `100`. Выбор сохраняется в `localStorage`; при следующем визите вспоминается. |

## 6. Кэширование в браузере (IndexedDB)

Чтобы не запрашивать ~2000 строк из Turso каждый F5 — все данные кешируются локально.

| Параметр | Значение |
|----------|----------|
| **Технология** | IndexedDB (не `localStorage`, не `sessionStorage`). |
| **База** | `FaucetAppDB` |
| **Объектное хранилище** | `snapshots` |
| **Ключ записи** | `real-v3` (инкрементируется при сбое кэша между версиями). |
| **Срок хранения** | До ручного сброса кнопкой **«⟳ Обновить»** или до очистки данных браузера. TTL нет (кэш считается «горячим», пока в `snapshot.fresh_until` не записан срок). |
| **Что хранится** | Готовый массив `finalRows` (после всех зачисток и расчётов), `captured_at`, `rawMedians`, `ratingConfig`. Всё, что нужно для мгновенной отрисовки за 0–50 мс. |
| **Когда кэш инвалидируется** | 1) Явный клик по «⟳ Обновить»; 2) Меняется версия ключа `real-v3` в коде; 3) `captured_at` свежего ответа Turso новее `cached.captured_at` |

Подробнее: функции `openAppCache`, `cacheGetLatest`, `cachePutLatest` в [app.js](../app.js).
