# Безопасность и секреты

⚠️ **КРИТИЧЕСКИ ВАЖНЫЙ РАЗДЕЛ. ПЕРЕЧИТАЙТЕ ЕГО ПЕРЕД КАЖДЫМ КОММИТОМ.**

Несоблюдение этих правил приведёт к компрометации БД Turso (потеря всех данных,
возможность скамма от имени вашего дашборда, денежные убытки на Turn.io по тарифам).

---

## 1. Принцип разделения токенов — основа безопасности

В проекте **два разных токена Turso** для двух разных сценариев. **Никогда не смешивайте их.**

| Тип | Публичный? | Доступ | Где используется |
|-----|:-----------:|--------|------------------|
| **READ-ONLY** (только чтение) | ✅ **ДА, МОЖНО ПУБЛИКОВАТЬ В КОД.** | `SELECT` только по таблицам. Нельзя `INSERT/UPDATE/DELETE/DROP`. Нельзя сменить пароль админа. | 1) Вшит в поле `TURSO_READONLY_TOKEN` файла [app.js](../app.js).<br>2) Используется главной таблицей для всех пользователей. |
| **WRITE-READ** (полный доступ) | ❌ **НИКОГДА НЕ ПУБЛИКОВАТЬ В КОД. НИКОГДА НЕ КОММИТИТЬ.** | ВСЕ привилегии. Можно удалить все строки в `faucets`, обнулить рейтинги, скомпрометировать targets_moderation. | 1) Только **GitHub Actions Secrets** → `TURSO_TOKEN` (используется пайплайном).<br>2) Только локальный файл **`Turso_DB_Connection.md`** (записан в `.gitignore`).<br>3) Вводится вручную в модалке админпанели (хранится только в `sessionStorage` вкладки). |

## 3. Как добавить / обновить секрет в GitHub Actions

1. Откройте **Settings** вашего репозитория (вкладка сверху справа).
2. Левое меню: **Secrets and variables → Actions**.
3. Кнопка **New repository secret**.
4. Поле **Name**: строго как в таблице (чувствительно к регистру!): `TURSO_TOKEN`, не `Turso_Token` и не `turso_token`.
5. Поле **Secret**: вставьте значение из `Turso_DB_Connection.md`.
6. **Add secret** → готово.

> ✅ Правильно добавленный секрет: в списке отображается как `TURSO_TOKEN = ••••••••`, его **нельзя скопировать / прочитать обратно** (только обновить или удалить). Это нормально, так и должно быть.

## 4. Почему в app.js лежит READ-ONLY токен — это безопасно?

Да. **READ-ONLY токен в app.js — это ожидаемое, штатное поведение по модели threat** этого проекта:
- Проект — публичный дашборд. Любой пользователь должен читать таблицу без логина.
- READ-ONLY токен позволяет только `SELECT * FROM faucets / raw_hourly / config / targets_moderation`.
- Даже если злоумышленник украдёт этот токен из DevTools → **он не сможет ничего записать или удалить**.

Если вы всё равно опасаетесь — можно ограничить READ-ONLY токен на стороне Turso ещё жёстче:
- IP whitelist (GitHub Pages + ваши домашние IP)
- Row-level security (только `mode='prod'` из config)

## 5. Безопасность админпанели

| Риск | Как смягчено |
|------|-------------|
| Кража WRITE токена через DevTools | Хранится **только в `sessionStorage`** вкладки. Закрыл вкладку → токен исчез. |
| Brute-force UI-пароля | Пароль даёт только доступ к UI-полям. Без правильного WRITE токена Turso — любые правки в админке просто не сохранятся в БД (Turso вернёт 401). |
| Подбор WRITE токена через JS-инъекцию | `sessionStorage` изолирован per-origin. XSS-инъекция в сторонний домен не достанет его. |
| CSRF на Turso | Библиотека `@libsql/client` (браузерная версия) отправляет `Origin` заголовок; Turso проверяет его. |

## 6. Как сменить WRITE-READ токен при компрометации

Если вы случайно закоммитили `TURSO_TOKEN` в публичный репозиторий или отправели его не туда — **действуйте за 3 шага**:

1. **НЕМЕДЛЕННО отзывайте токен в панели Turso → Settings → Database tokens → Revoke**. Это важнее всего.
2. **Выпускайте новый токен** с тем же набором прав (`Full-access`).
3. Обновите:
   - Локальный файл **`Turso_DB_Connection.md`**
   - GitHub Repository Secret **`TURSO_TOKEN`** (Settings → Secrets and variables → Actions)
4. (Опционально) Запустите workflow **Fetch Faucets** вручную → убедитесь, что он зелёный с новым токеном.

## 7. Проверка секретов перед каждым коммитом (Checklist)

✅ Создавайте привычку прогонять этот чек-лист перед `git add`:

- [ ] Я не правил `Turso_DB_Connection.md` сегодня? Если правил — точно ли он в `.gitignore`?
- [ ] Я не вставил `TURSO_TOKEN` (WRITE) в app.js, build_faucets.js, ratingCalculator.js?
- [ ] Я сделал `git status` и в списке изменённых нет `Turso_DB_Connection.md`?
- [ ] Я не оставил в console.log / console.warn значение WRITE токена?
- [ ] В app.js `TURSO_READONLY_TOKEN` — действительно READ ONLY? (Проверьте в Turso Dashboard.)

> ❌ Если хотя бы один пункт не прошёл — **НЕ ДЕЛАЙТЕ PUSH**. Удалите секрет, запушьте после исправлений.

## 8. Уязвимости, НЕ относящиеся к токенам

| Вектор атаки | Что сделано |
|-------------|-------------|
| SQL Injection через поиск | Поиск работает **в памяти браузера** через `filter()` по уже загруженному массиву. Ни один пользовательский ввод не передаётся в `WHERE`-условие Turso. |
| XSS в названии крана | Все значения экранируются через `textContent` браузерного API. `innerHTML` используется только для проверенных бейджей (статические классы). |
| Clickjacking | В GitHub Pages по умолчанию есть `X-Frame-Options: DENY`. |
| Рейтинг-манкипулейция через raw API call | Пайплайн `build_faucets.js` запускается **только GitHub Actions** с секретом `TURSO_TOKEN`. Браузер не может запустить его. |

## 9. Что делать при инциденте

Если вы заподозрили компрометацию WRITE-READ токена или утечек:

1. Отзовите все Turso-токены в панели управления (пункт 6 выше).
2. Создайте issue в репозитории с меткой `security`.
3. Скачайте последний валидный экспорт модерации через админпанель (📤 Export JSON).
4. Запустите init_db.js на новой пустой БД и залейте обратно данные из `faucets.json` + `moderation.json`.
5. Информируйте пользователей через Issue.
