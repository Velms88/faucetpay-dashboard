# База данных Turso

В проекте используется **Turso** — edge-SQLite БД от libsql.org, совместимая с SQLite-протоколом и
драйвером `@libsql/client`. Всего используется 4 таблицы.

---

## 1. Безопасность: разделение токенов

⚠️ **КРИТИЧЕСКИ ВАЖНО. НИКОГДА НЕ КОММИТЬТЕ WRITE-READ ТОКЕН В КОД.**

| Тип токена | Где используется | Уровень доступа |
|-----------|------------------|---------------|
| **READ ONLY (публичный)** | Вшит прямо в `app.js` в поле `TURSO_READONLY_TOKEN` | `SELECT` по всем таблицам (не может `INSERT/UPDATE/DELETE/DROP`). Безопасен для публикации в браузер. |
| **WRITE-READ (приватный)** | 1) GitHub Actions Secrets → `TURSO_TOKEN`<br>2) Локальный файл `Turso_DB_Connection.md` (НЕ КОММИТИТЬ!) | Полный доступ: `SELECT/INSERT/UPDATE/DELETE`. Используется только пайплайном `build_faucets.js` и админпанелью (вводится вручную в модалке входа). |

Дополнительно в разделе [Безопасность](SECURITY.md).

## 2. Создание таблиц

Если у вас пустая БД Turso — инициализируйте схему одной командой:

```cmd
npm run init-db
```

Это запустит [init_db.js](../init_db.js), который выполнит 4 SQL-запроса `CREATE TABLE IF NOT EXISTS`.

## 3. Список таблиц и их схема

### 3.1 `faucets` — основной список кранов (1 строка = 1 кран)

**Обновляется каждый запуск пайплайна (каждые ~13 мин).**

| Колонка | Тип | Назначение |
|---------|-----|-----------|
| `url` | `TEXT PRIMARY KEY` | Нормализованный URL крана (без `https://`, без слеша в конце) |
| `name` | `TEXT` | Название крана |
| `category` | `TEXT` | Категория (Faucet / PTC / Offerwall / Shortlink / …) |
| `currency_list` | `TEXT` | JSON-массив всех монет крана `["BTC","LTC",…]` |
| `coins_json` | `TEXT` | Детальный JSON балансы, paid_today, total_users_paid по каждой монете |
| `health_score` | `REAL` | Готовый Health Score (0–100) или `NULL` |
| `rating` | `REAL` | Готовый рейтинг (0–100) или `NULL`. **Для отображения всегда пересчитывается локально на клиенте.** |
| `rating_grade` | `TEXT(2)` | Буквенная оценка рейтинга: `A+`, `A`, `B`, `C`, `D`, `F` |
| `rating_breakdown` | `TEXT` | JSON: все промежуточные поля расчёта (блоки, веса, пороги) |
| `total_users_paid` | `TEXT` | Кол-во выплат за 24 ч (сырое из API) |
| `paid_today` | `TEXT` | Общий USD-объём выплат за 24 ч (число как текст) |
| `current_capital` | `REAL` | Текущий капитал крана в USD (баланс всех монет × курс) |
| `is_enabled` | `INTEGER(1)` | `1` если кран включён и работает; `0` если выключен модерацией |
| `raw_json` | `TEXT` | Полный слепок записи API FaucetPay. Используется как резервный источник. |
| `updated_at` | `TEXT` | ISO 8601-метка обновления этой строки |
| `age_months` | `REAL` | Возраст крана в месяцах (из таргета модерации) |
| `payout_type` | `TEXT` | Тип выплат: `Auto` / `Manual` / `Mixed` |
| `gateways_count` | `INTEGER` | Количество платёжных шлюзов |
| `block_1_solvency` / `block_2_reliability` / `block_3_uii` / `block_4_bonus` | `REAL` | Оценки по 4 блокам рейтинга (0–100). Используются для столбцов «Блок1% — Блок4%». |

---

### 3.2 `raw_hourly` — история всех снимков (1 кран × 1 час = 1 строка)

**Одна строка = один снимок состояния крана, сделанный пайплайном. Редактируется только пайплайном, никогда вручную.**

| Колонка | Тип | Назначение |
|---------|-----|-----------|
| `id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | Первичный ключ |
| `captured_at` | `TEXT` | ISO 8601-время снимка |
| `captured_day` | `TEXT` | Только дата YYYY-MM-DD, для быстрого группирования по дням |
| `url` | `TEXT` | FK → `faucets.url` |
| `coins_json` | `TEXT` | Все монеты крана (балансы, paid_today, total_users_paid по каждой) |
| `prices_json` | `TEXT` | Курсы криптовалют на момент снимка (CoinGecko) |
| `total_balance_usd` | `REAL` | Колонка **TOTAL_BALANCE**: сумма балансов всех монет × курс = капитал USD |
| `current_health` | `REAL` | Колонка **CURRENT_HEALTH**: здоровье на момент снимка, 0–100 |
| `median_health` | `REAL` | Колонка **МЕДИАНА HS**: медиана пиков Health Score за каждый день истории |
| `usd_paid_today` | `REAL` | Колонка **PAID_TODAY (USD)**: сумма по всем монетам × курс (после антинакрутки) |
| `total_users_paid` | `INTEGER` | Колонка **TOTAL_USERS_PAID**: сырой счётчик из API (но зачищенный на запись) |
| `health_reference_usd` | `REAL` | USD-медиана балансов за 7 дней (для вычисления CURRENT_HEALTH) |

---

### 3.3 `targets_moderation` — ручные модераторские таргеты

Задаются из админпанели. Переопределяют «автоматические» значения, пришедшие из API.

| Колонка | Тип | Назначение |
|---------|-----|-----------|
| `url` | `TEXT PRIMARY KEY` | → `faucets.url` |
| `is_enabled` | `INTEGER(1)` | `0` = кран принудительно выключен, `1` = включён |
| `age_months` | `REAL` | Возраст сайта в месяцах (ручная модерация) |
| `payout_type` | `TEXT` | `Auto` / `Manual` / `Mixed` (ручная перезапись) |
| `gateways_count` | `INTEGER` | Количество шлюзов (ручная перезапись) |
| `uii_points` | `REAL` | **UII**: баллы пользовательского индекса (Блок 3, 0–100) |
| `bonus_points` | `REAL` | **Bonus Points** (Блок 4, 0–100), снимаются за нарушения/накрутки |
| `label` | `TEXT` | Метка в таблице: `LEGIT` / `SCAM` / `NEW` / `МОЙ` |
| `created_at` / `updated_at` | `TEXT` | Метки времени |

---

### 3.4 `config` — конфигурация формул рейтингов

Задаёт веса и пороги для Health Score и Rating (Режим `prod`). Одна строка = один профиль настроек.
Полную структуру см. в разделе [Конфигурация формул](CONFIG.md).

| Колонка | Тип |
|---------|-----|
| `mode` | `TEXT PRIMARY KEY` (обычно `prod`) |
| `health` | `TEXT` — JSON с порогами Health Score |
| `rating` | `TEXT` — JSON с весами Блоков 1–4, порогами всех шкал, порогами A–F |
| `updated_at` | `TEXT` |

## 4. Связи между таблицами

```
 faucets.url (PK)  <─────────┐
                             │
 targets_moderation.url (PK) ─┤  1 : 1 (на каждый кран
                             │           максимум 1 таргет)
                             │
 raw_hourly.url (INDEX) ─────┘  1 : N (на каждый кран
                                        много снимков истории)
```

## 5. Индексы (для быстродействия)

| Таблица | Индекс | Зачем |
|---------|--------|-------|
| `raw_hourly` | `(url, captured_at DESC)` | Быстрый выбор последнего снимка по URL |
| `raw_hourly` | `(url, captured_day)` | Группировка «пик каждого дня» для медиан |
| `faucets` | `(is_enabled, rating DESC)` | Быстрая сортировка главной таблицы |

Более детально SQL — см. [init_db.js](../init_db.js).
