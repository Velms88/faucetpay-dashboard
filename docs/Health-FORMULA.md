# Health Score — Формула расчёта (FINAL SPEC)

**Версия документа: v1.3**  
Действует на клиенте (`clientCalc.calculateHealthScore` в [app.js](../app.js)) и на сервере (`calculateHealthScore` в [healthScore.js](../healthScore.js)).  
Формулы на клиенте и сервере ОБЯЗАТЕЛЬНО должны быть симметричны (выдавать одинаковое число при одинаковых входах).

---

## 0. Базовые понятия

**Health Score** (Показатель «Здоровье» крана) — это число **0–100**, которое отвечает на вопрос:
> «Насколько текущий капитал крана близок к своему историческому максимуму за окно наблюдения?»

- **100** — кран сейчас на всём историческом пике капитала (идеально).
- **50** — текущий капитал ровно в два раза меньше пикового (средне).
- **0** — баланс пустой или близкий к пустому.

---

## 1. Базовая формула расчёта

```
ЭТАЛОННЫЙ_КАПИТАЛ_USD = MAX( total_balance_usd за все снимки за retention_days )

ТЕКУЩИЙ_КАПИТАЛ_USD  = SUM( кошелёк[currency] * цена[currency] ) по всем монетам крана

HS_БАЗОВЫЙ = ТЕКУЩИЙ_КАПИТАЛ_USD / ЭТАЛОННЫЙ_КАПИТАЛ_USD  × 100
```

### Где в БД хранятся исходные данные:
| Поле | Таблица / колонка | Комментарий |
|------|-------------------|-------------|
| `ТЕКУЩИЙ_КАПИТАЛ_USD` | `raw_hourly.total_balance_usd` | Колонка **TOTAL_BALANCE** |
| `ЭТАЛОННЫЙ_КАПИТАЛ_USD` | `MAX(total_balance_usd) WHERE url=? AND captured_at > now() - retention_days` | Задаётся в конфиге `health.retention_days` (по умолчанию 7 дней) |

## 2. Корректирующие коэффициенты (для кранов с низким капиталом)

Для кранов с очень маленьким капиталом базовая формула даёт нерепрезентативные числа.
Поэтому применяются **3 условия**, переопределяющие результат.

### ✅ Условие 1. Микро-капитал (< $0.01)
```
IF  ЭТАЛОННЫЙ_КАПИТАЛ_USD < 0.01 USD
   AND ТЕКУЩИЙ_КАПИТАЛ_USD < 0.01 USD
THEN  HS_FINAL = 0
```
*Комментарий*: если кран никогда не имел на балансе даже 1 цента — его «здоровье» равно нулю.

### ✅ Условие 2. Низкий капитал (от $0.01 до $0.99)
```
IF  0.01 ≤ ЭТАЛОННЫЙ_КАПИТАЛ_USD ≤ 0.99 USD
THEN  HS_FINAL = HS_БАЗОВЫЙ × ЭТАЛОННЫЙ_КАПИТАЛ_USD
```
*Комментарий*: домножаем на доллары — чем меньше кран, тем сильнее «наказываем» его HS. Например: пик = $0.50, текущий = $0.50 → HS_базовый = 100, HS_final = 100 × 0.50 = 50.

### ✅ Условие 3. Нормальный капитал (≥ $1)
```
IF  ЭТАЛОННЫЙ_КАПИТАЛ_USD ≥ 1.00 USD
THEN  HS_FINAL = HS_БАЗОВЫЙ (округлить до 2 знаков)
```
*Комментарий*: штатный режим для большинства кранов.

### ✅ Условие 4. Нет истории (0 снимков)
```
IF  COUNT(raw_hourly captures) == 0
THEN  HS_FINAL = «—» (прочерк, NULL)
```

## 3. Примеры расчётов

### Пример №1: Кран viefaucet.com (топ, нормальный капитал)
- Пиковый капитал за 7 дней: `$18,204.10` (≥ $1 → Условие 3)
- Текущий капитал: `$17,905.45`
- `HS_баз = 17905.45 / 18204.10 × 100 ≈ 98.36`
- **HS_финал = 98.4**

### Пример №2: Кран smallcoin.biz (низкий капитал)
- Пиковый капитал за 7 дней: `$0.40` (0.01–0.99 → Условие 2)
- Текущий капитал: `$0.40`
- `HS_баз = 0.40/0.40 × 100 = 100`
- `HS_финал = 100 × 0.40 = 40`

### Пример №3: Кран microdust.xyz (микро-капитал)
- Пиковый капитал: `$0.007` (< $0.01) и текущий `$0.005`
- → **Условие 1** → **HS_финал = 0**

### Пример №4: Новый кран newfaucet.io
- Истории снимков ещё нет (`count = 0`)
- → **Условие 4** → `NULL` (в UI показывается прочерк `—`)

### Пример №5: Пылевой кран dust-trap.io (текущая версия, антинакрутка)
Антинакрутка для Health Score применяется ТОЛЬКО косвенно через Рейтинг (Блок 1 Блок2 Блок3).
Напрямую формула Health Score не учитывает paid_today — она учитывает ТОЛЬКО капитал и пик капитала.

## 4. Где в коде хранится формула

### Клиент (браузер)
Функция `clientCalc.calculateHealthScore` → [app.js](../app.js) (ищите `calculateHealthScore:`).
Расчитывается повторно на клиенте при каждой загрузке страницы.

### Сервер (GitHub Actions пайплайн)
Функция `module.exports.calculateHealthScore` → [healthScore.js](../healthScore.js).
Расчитывается один раз в час и записывается в колонку `faucets.health_score` + `raw_hourly.current_health`.

---

## 5. Параметры, которые можно настроить без кода

Все параметры ниже лежат в JSON `health` в строке `mode='prod'` таблицы `config` БД Turso
(подробнее — [Конфигурация формул](CONFIG.md)):

| Параметр | Значение по умолчанию | Где влияет |
|----------|:---------------------:|-----------|
| `health.retention_days` | `7` | Ширина окна расчёта эталонного пика (по умолчанию максимум за 7 дней, а не за всю историю) |
| `health.micro_capital_usd` | `0.01` | Порог Условия 1 (ниже → HS всегда 0) |
| `health.low_capital_usd` | `1.00` | Порог Условия 2/3 |

## 7. Проверка симметрии (regression test)

Перед каждым коммитом в healthScore.js / app.js запускайте:
```cmd
node build_faucets.js --dry-run --mock-prices
```
Сравните столбец `health_score` из stdout пайплайна со столбцом «Здоровье» в браузере на одинаковых
входных data-snapshot. Дельта по модулю **не должна превышать 0.01** на 99% кранов.
